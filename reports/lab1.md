## ch3实验报告
### 实现功能
实现了一个新的系统调用sys_trace。系统调用编号为410，它能够用来追踪当前任务系统调用的历史信息，并做对应的修改,包括地址读取，数据写入和调用数量统计。
### 实现方式
+ 对于地址的操作将输入的id视作uszie指针做对应处理即可。
+ 系统调用统计使用了线性表结构，采用两个64大小的usize数组ids、counts进行实现。通过将Task结构体拓展了对应的线性表结构，我们每次调用时都会将线性表对应的系统调用次数加一，进而实现了系统调用数量的更新与统计。

> L40：刚进入 __restore 时，sp 代表了什么值。请指出 __restore 的两种使用情景。

进入__restore时,sp代表内核栈的栈顶。__restore的功能是根据保存在内核栈上的Trap上下文恢复寄存器，同时返回用户态。因此，__restore函数的两种使用情景为当批处理操作系统初始化完成，或者是某个应用程序运行结束或出错的时候，此时需要切换到下一个应用程序，因此需要实现上下文的恢复和切换到用户态，使用__restore函数实现。

> L43-L48：这几行汇编代码特殊处理了哪些寄存器？这些寄存器的的值对于进入用户态有何意义？请分别解释。
```
ld t0, 32*8(sp)
ld t1, 33*8(sp)
ld t2, 2*8(sp)
csrw sstatus, t0
csrw sepc, t1
csrw sscratch, t2
```
这几行代码实现了CSR信息的恢复。
+ 其中sstatus信息存储在内核栈中第32个寄存器中，该字段可以给出给出 Trap 发生之前 CPU 处在哪个特权级（S/U）等信息作为恢复用户态的凭证。
+ sepc信息存储在内核栈中第33个寄存器中，它记录着记录 Trap 发生之前执行的最后一条指令的地址
+ sscratch信息存储在内核栈中第二个寄存器中，它保存着用户栈的栈指针，它在最后会和sp指针进行信息交换，使得sp指针指向用户栈。

> L50-L56：为何跳过了 x2 和 x4

```
ld x1, 1*8(sp)
ld x3, 3*8(sp)
.set n, 5
.rept 27
   LOAD_GP %n
   .set n, n+1
.endr
```
x2保存着用户栈的栈指针，在之前就被读取至t2寄存器中。而x4寄存器一般应用程序根本不会用到，因此同样跳过。
> L60：该指令之后，sp 和 sscratch 中的值分别有什么意义？
```
csrrw sp, sscratch, sp
```
该指令实现了sp指针和sscratch指针内容的交换，该指令前，sp指针指向内核栈，sscratch指针指向用户栈。指令之后,sp指针指向用户栈栈顶、sscratch指针指向内核栈栈顶。
> __restore：中发生状态切换在哪一条指令？为何该指令执行之后会进入用户态

__restore中发生状态切换的指令为sret。当执行 sret 时，CPU 根据 SPP 的值决定恢复的特权级：

若 SPP = 0，执行 sret 后，CPU会切换到 U 态。

若 SPP = 1，执行 sret 后，CPU会保持在 S 态
因为在内核态执行sret执行，因此CPU会切换为用户态。
> L13：该指令之后，sp 和 sscratch 中的值分别有什么意义
```
csrrw sp, sscratch, sp
```
该指令实现了sp指针和sscratch指针内容的交换，该指令前，sp指针指向用户栈，sscratch指针指向内核栈。指令之后,sp指针指向内核栈栈顶、sscratch指针指向用户栈栈顶。
> 从 U 态进入 S 态是哪一条指令发生的

用户态syscall调用后进入内核态。
