#### 问答作业
> 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

SV39的页表项组成为Reserved(54-63)+物理地址(10-53)+预留位(8-9)+标志位(0-7),其中，标志位的位置及其对应功能如下所示:
+ V(0):Valid,有效位，证明该页表项是否合法。
+ R(1):Read,可读位，证明该页面是否可读。
+ W(2):Write,可写位，证明该页面是否可写。
+ X(3):Excute,可执行位，证明该页面是否可执行。
+ U(4):User,用户位,指示该页面是否在用户态可访问。
+ G(5):Global,全局位，指示该页面是否对所有地址空间可见。
+ A(6):Accessed,访问位，指示该页面是否被访问过。
+ D(7):Dirty,脏位，指示该页面是否被修改过。
> 缺页指的是进程访问页面时页面不在页表中或在页表中无效的现象，此时 MMU 将会返回一个中断， 告知 os 进程内存访问出了问题。os 选择填补页表并重新执行异常指令或者杀死进程。
+ 请问哪些异常可能是缺页导致的？
+ 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。

缺页异常可能导致的异常类型：

+ 访问未映射的虚拟地址：进程尝试访问尚未建立映射的虚拟地址，导致 MMU 触发缺页异常。

+ 访问权限不足：进程尝试写入只读页面或执行不可执行页面，导致访问权限异常。

缺页发生时的重要寄存器值：

+ satp（Supervisor Address Translation and Protection）：存储当前页表的基地址，指向根页表。

+ stval（Store Trap Value）：存储导致异常的虚拟地址，帮助 OS 识别缺页位置。

+ scause（Supervisor Cause Register）：存储异常原因，可能指示访问权限错误或页面缺失。

+ sstatus（Supervisor Status Register）：记录当前特权级和 MMU 状态，影响缺页处理方式。
> 缺页有两个常见的原因，其一是 Lazy 策略，也就是直到内存页面被访问才实际进行页表操作。 比如，一个程序被执行时，进程的代码段理论上需要从磁盘加载到内存。但是 os 并不会马上这样做， 而是会保存 .text 段在磁盘的位置信息，在这些代码第一次被执行时才完成从磁盘的加载操作。

这样做有哪些好处？
+ 减少内存占用： 进程启动时不会立刻将所有代码段和数据段加载到内存，而是只在需要时加载，从而减少不必要的内存分配，提高物理内存的利用率。

+ 加快进程启动速度： 由于不需要在进程启动时完成全部页面的分配和映射，减少了启动时的磁盘 I/O 开销，使进程能够更快进入运行状态。

+ 降低磁盘 I/O 开销： 只加载实际访问的页面，避免了一次性加载大量可能不会使用的数据，从而减少磁盘读写，提高系统整体性能。

> 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？

每页大小为4K,10G对应2.5M页。而每个页都需要3级页表，对于第三级页表，需要2.5M个页表项,占用大小为2.$5M*8B$=20MB,对于第二级页表，需要2.5M/512=5K个页表项，占用大小为$5K*8B=40KB$,对于第一级页表，占用大小为$80B$,所以，页表占用大小约为20MB.

> 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。

+ 在页表项内容上拓展一个分配位，初始标记为0代表不分配，需要时访问该区域触发缺页异常，接着标记为1，更新页表并重新访问。
+ 当发生缺页时，进入异常处理模式，首先查看页表，确认访问地址为lazy分配策略。接着进行物理页分配，并更新页表项使之指向新分配物理页，接着重新执行缺页指令

> 缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。此时页面失效如何表现在页表项(PTE)上？

+ PTE 的 Valid（V）位被清除，表示该页无效。
+ PPN（物理页号）字段可能被替换为 swap 位置，用于记录该页在磁盘上的存储位置。
+ 访问该页时触发缺页异常，OS 需要从磁盘加载该页并恢复 PTE。
> 在单页表情况下，如何更换页表？
+ 保存当前进程的页表信息。
+ 加载新进程的页表地址，并更新satp寄存器。
+ 刷新TLB，确保新的页表生效

> 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）
+ 通过页表项中的U字段实现，设置内核模式页面的U字段为0，这样在用户态进行访存操作时会触发异常。
> 单页表有何优势？（回答合理即可）
+ 减少页表切换开销：进程在用户态和内核态切换时无需更换页表，提高上下文切换效率。

+ 减少内存占用：单页表避免了维护两张页表的额外开销，节省内存。

> 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）
+ 进入内核态时：切换到内核页表，确保内核地址空间隔离。

+ 返回用户态时：切换回用户页表，恢复用户进程的地址空间。

如果采用单页表设计，我会选择在 进程切换时 更换页表，而不是在用户态和内核态切换时，以减少页表切换的开销。
